# chatsync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An npm CLI, `chatsync`, that copies Claude desktop Code-tab sidebar entries between signed-in accounts on one Mac so every account lists every chat, with backups and no deletions.

**Architecture:** A pure planner (`src/plan.js`) turns the on-disk entries, the active account and the last-sync state into a list of writes and conflicts. Thin I/O modules read the app's folders (`store.js`), back up and restore (`backup.js`), and apply a plan (`apply.js`). `bin/chatsync.js` parses arguments and runs an interactive menu when given no command.

**Tech Stack:** Node ≥ 18, ESM, plain JavaScript, zero runtime dependencies, `node:test` + `node:assert/strict`, `node:util` `parseArgs`, `node:readline/promises`.

**Spec:** `docs/specs/2026-10-22-chatsync-design.md`

## Global Constraints

- Node ≥ 18 (`"engines": { "node": ">=18" }`), `"type": "module"`, no `dependencies` in package.json.
- Package name `chatsync` (unscoped), binary `chatsync`, MIT license, `files: ["bin", "src", "README.md", "LICENSE"]`.
- macOS only in v1; app data dir is `~/Library/Application Support/Claude`.
- Sessions folder: `<appDir>/claude-code-sessions/<accountId>/<orgId>/local_<id>.json`.
- Active account: `lastKnownAccountUuid` in `<appDir>/config.json`.
- Machine names: `<appDir>/ssh_configs.json` → `configs[].name` keyed by `configs[].sshHost`.
- chatsync home: `~/.chatsync/` holding `backups/`, `state.json`, `config.json`.
- Backups named `YYYY-MM-DD_HHMMSS` (local time), keep newest 20.
- Never write any org folder of the active account. Never delete an entry.
- Only `local_*.json` files are entries; other files in account folders are never touched.
- Writes are atomic: temp file in the same folder, then `rename`.
- Exit codes: 0 ok, 1 error, 2 unsupported platform or unrecognized data layout.
- No prompts when stdin is not a TTY or `-y` is passed.

## Review Focus

1. **Active account unknown** (`config.json` missing or no `lastKnownAccountUuid`): sync must refuse to write (exit 2), since it cannot know which folder the app owns. Test in Task 2 and Task 7.
2. **Dotfiles in the sessions tree** (`.DS_Store` beside account folders): ignored, not treated as an unrecognized layout. Test in Task 2.
3. **Entry being written by the app** (truncated JSON) or missing `sessionId`/`lastActivityAt`: stop with exit 2 before backup or writes. Test in Task 2 and Task 5.
4. **`chatsync sync` piped / in a script without `-y`**: print the plan, write nothing, exit 1 with "pass -y to apply". Test in Task 7.
5. **Backup fails** (e.g. backups dir not writable): no entry is written. Test in Task 5.

### Task 3: The planner (`plan.js`)

**Files:**
- Create: `src/plan.js`
- Test: `test/plan.test.js`

**Interfaces:**
- Consumes: store shape from Task 2
- Produces: `buildPlan({ store, activeAccountId, state }) → Plan`
  - `state = { sessions: { [sessionId]: { [accountId]: lastActivityAt } } }` (may be `{}`)
  - `Plan = { chats: Chat[], writes: Write[], conflicts: Conflict[], unchanged: number }`
  - `Chat = { sessionId, newest: Entry, copies: Entry[] }` (all chats, for status)
  - `Write = { sessionId, accountId, orgId, kind: 'copy' | 'update', from: { accountId, orgId }, data }` where `data` is `newest.data`
  - `Conflict = { sessionId, title, accountIds: string[] }`
  - throws `ChatsyncError('Cannot tell which account is active…', 2)` when `activeAccountId` is null or not in `store.accounts`

**Rules** (spec "Sync rules"; this is the algorithm the tests do not fully pin):
- Group entries by `data.sessionId`. `newest` = max `lastActivityAt`; ties broken by active account first, then account id order.
- For each inactive account `X`:
  - if `X` has copies of the chat: for each such copy, `update` when `copy.lastActivityAt < newest.lastActivityAt`, else count `unchanged`.
  - else target orgs = `X`'s org folders that contain ≥1 entry; if none, `X`'s org with id `newest.orgId` if present, else `X.orgs[0]`; if `X` has no org folders, create none (skip). One `copy` per target org.
- Conflict: accounts whose copy `lastActivityAt` is greater than `state.sessions[id][acc]` (only accounts that have a state value count); ≥ 2 such accounts → conflict.

- [ ] **Step 1: Write failing tests**
  - `copies a chat only in A to inactive B` — active A → one `copy` into B's org
  - `round trip A→B→A` — A@100, B@200, active B → `update` into A with B's data; then with A@200, B@200 → no writes, `unchanged` 1
  - `never writes the active account` — B newer, active A → no write targets A
  - `writes to every org of the target that has chats` — B has ORG1 and ORG2 with entries → 2 copies
  - `target with no populated org uses source org id` — B has empty ORG2 and ORG1, newest from ORG2 → copy into ORG2
  - `archived newest copy propagates isArchived` — `data.isArchived === true` in the write
  - `conflict when two accounts changed since last state` — state {A:100,B:100}, A@150, B@160, C inactive → conflict lists A,B; newest is B
  - `null or unknown active account throws exit 2`
- [ ] **Step 2: Run** `node --test test/plan.test.js` — Expected: FAIL
- [ ] **Step 3: Implement** `src/plan.js` (pure; no `fs`).

**Interfaces:**
- Consumes: `Plan` (Task 3), `createBackup`, `pruneBackups` (Task 4)
- Produces:
  - `loadState(home) → state` (`{ sessions: {} }` when missing or unparsable), `saveState(home, state)` (atomic)
  - `applyPlan(plan, { sessionsDir, home, now }) → { backup: string | null, written: number, pruned: string[] }`
    - if `plan.writes` is empty: write nothing, no backup, still save state
    - else: `createBackup` first (any throw aborts before writes), then for each write: `<sessionsDir>/<accountId>/<orgId>/<sessionId>.json`, temp `.<sessionId>.json.chatsync-tmp` then `rename`, JSON written with no extra formatting (`JSON.stringify(data)`), then `pruneBackups`
    - new state: for every chat, every account that holds it after the writes → `newest.data.lastActivityAt`
