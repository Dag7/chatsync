# chatsync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An npm CLI, `chatsync`, that copies Claude desktop Code-tab sidebar entries between signed-in accounts on one Mac so every account lists every chat, with backups and no deletions.

**Architecture:** An Nx workspace whose one project, `packages/chatsync`, is the published package. A pure planner (`plan.ts`) turns the on-disk entries, the active account and the last-sync state into writes and conflicts. Thin I/O modules read the app's folders (`store.ts`), back up and restore (`backup.ts`) and apply a plan (`apply.ts`). `program.ts` builds a commander program whose every seam is injectable (`ProgramDeps`); `index.ts` only wires the real process.

**Tech Stack:** yarn 4 workspaces, Nx 23, TypeScript 6 (`tsc`, NodeNext ESM), vitest 4, ESLint 10 + typescript-eslint + Prettier, `commander`, `@inquirer/prompts`. Reference setup: `~/Desktop/repo/oramono` (root `nx.json`, `tsconfig.base.json`, `eslint.config.mjs`, `.prettierrc`, `.yarnrc.yml`, `vitest.shared.ts`; package `packages/node/ora-cli`).

**Spec:** `docs/specs/2026-10-22-chatsync-design.md`

## Global Constraints

- Node ≥ 20 (`"engines": { "node": ">=20" }`), `"type": "module"`, TypeScript `strict` with oramono's `tsconfig.base.json` options; no `any` (ESLint error, use `unknown` + narrowing).
- Package `packages/chatsync`: name `chatsync` (unscoped), `bin: { "chatsync": "./dist/index.js" }`, `files: ["dist", "README.md", "LICENSE"]`, MIT, `publishConfig.access: public`. Root `package.json` is `private: true`.
- Runtime dependencies only `commander` and `@inquirer/prompts`.
- Tests colocated as `src/**/*.test.ts`, run with vitest; never collect from `dist/`.
- Relative imports use `.js` suffixes (NodeNext).
- macOS only in v1; app data dir is `~/Library/Application Support/Claude`.
- Sessions folder: `<appDir>/claude-code-sessions/<accountId>/<orgId>/local_<id>.json`.
- Active account: `lastKnownAccountUuid` in `<appDir>/config.json`.
- Machine names: `<appDir>/ssh_configs.json` → `configs[].name` keyed by `configs[].sshHost`.
- chatsync home: `~/.chatsync/` holding `backups/`, `state.json`, `config.json`. Every `home` parameter below means this directory.
- Backups named `YYYY-MM-DD_HHMMSS` (local time), keep newest 20.
- Never write any org folder of the active account. Never delete an entry.
- Only `local_*.json` files are entries; other files in account folders are never touched.
- Writes are atomic: temp file in the same folder, then `rename`.
- Exit codes: 0 ok, 1 error, 2 unsupported platform or unrecognized data layout.
- No prompts when stdin is not a TTY or `-y` is passed.

## Review Focus

1. **Active account unknown** (`config.json` missing or no `lastKnownAccountUuid`): sync refuses to write (exit 2). Tests in Task 2 and Task 7.
2. **Dotfiles in the sessions tree** (`.DS_Store`): ignored, not an unrecognized layout. Test in Task 2.
3. **Entry being written by the app** (truncated JSON) or missing `sessionId`/`lastActivityAt`: exit 2 before backup or writes. Tests in Task 2 and Task 5.
4. **`chatsync sync` piped / scripted without `-y`**: print the plan, write nothing, exit 1 with "pass -y to apply". Test in Task 7.
5. **Backup fails** (backups dir not writable): no entry written. Test in Task 5.

### Task 3: The planner (`plan.ts`)

**Files:**
- Create: `packages/chatsync/src/plan.ts`
- Test: `packages/chatsync/src/plan.test.ts`

**Interfaces:**
- Consumes: `Store`, `Entry`, `EntryData` (Task 2); `test-helpers`
- Produces:
  - `type SyncState = { sessions: Record<string, Record<string, number>> }`
  - `type Chat = { sessionId: string; newest: Entry; copies: Entry[] }`
  - `type Write = { sessionId: string; accountId: string; orgId: string; kind: "copy" | "update"; from: { accountId: string; orgId: string }; data: EntryData }`
  - `type Conflict = { sessionId: string; title: string; accountIds: string[] }`
  - `type Plan = { chats: Chat[]; writes: Write[]; conflicts: Conflict[]; unchanged: number }`
  - `buildPlan(input: { store: Store; activeAccountId: string | null; state: SyncState }): Plan` — pure, no `fs`; throws `ChatsyncError("Cannot tell which account is active in Claude…", 2)` when `activeAccountId` is null or not in `store.accounts`

**Rules** (spec "Sync rules"; the part the tests do not fully pin):
- Group entries by `data.sessionId`. `newest` = max `lastActivityAt`; ties: active account first, then account id order.
- For each inactive account `X`:
  - if `X` has copies: per copy, `update` when `copy.lastActivityAt < newest.lastActivityAt`, else count `unchanged`.
  - else targets = `X`'s orgs with ≥ 1 entry; if none, `X`'s org whose id is `newest.orgId` if present, else `X.orgs[0]`; `X` with no orgs → skip. One `copy` per target.
- Conflict: accounts whose copy `lastActivityAt` > `state.sessions[id][acc]` (only accounts with a state value count); ≥ 2 → conflict.

- [ ] **Step 1: Write failing tests**
  - `copies a chat only in A to inactive B` — active A → one `copy` into B's org
  - `round trip A→B→A` — A@100, B@200, active B → `update` into A with B's data; then A@200, B@200 → no writes, `unchanged` 1
  - `never writes the active account` — B newer, active A → no write targets A
  - `writes to every org of the target that has chats` — B has ORG1 and ORG2 with entries → 2 copies
  - `target with no populated org uses source org id` — B has empty ORG1 and ORG2, newest from ORG2 → copy into ORG2
  - `archived newest copy propagates isArchived`
  - `conflict when two accounts changed since last state` — state {A:100,B:100}, A@150, B@160, C inactive → conflict accountIds [A,B], newest B
  - `null or unknown active account throws exit 2`
- [ ] **Step 2: Run** `yarn nx test chatsync` — Expected: FAIL
- [ ] **Step 3: Implement** `plan.ts`.
- [ ] **Step 4: Run** `yarn nx run-many -t test typecheck lint` — Expected: PASS
